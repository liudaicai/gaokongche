# 高空车租赁管理系统 - 多租户方案设计

> **文档版本**: v1.0  
> **创建时间**: 2024-12-23  
> **适用版本**: v1.0+

---

## 📊 现状分析

### ✅ 已具备的基础
1. **数据库表**：26个核心表已包含 `company_id` 字段
2. **用户表结构**：`users` 表已有 `company_id` 和 `role` 字段
3. **认证体系**：JWT token 包含用户信息（`req.user`）
4. **公司认证表**：`company_verifications` 表存储公司主体信息

### ❌ 存在的问题
1. **无数据隔离**：后端API未实现 `company_id` 过滤
2. **权限混乱**：`role` 字段值不统一（admin/manager/user/superadmin等）
3. **跨租户访问**：任何用户都能看到所有公司的数据
4. **代码分散**：缺少统一的多租户中间件

## 🎯 七种多租户方案对比

### 方案一：**渐进式数据隔离（WHERE过滤）**（推荐⭐⭐⭐⭐⭐）

**核心思路**：保持现有数据库结构，通过中间件 + WHERE 条件实现数据隔离

#### ✅ 优点
- **实施成本最低**：无需数据库迁移，只需修改后端代码
- **风险最小**：渐进式推进，可逐个模块验证
- **兼容性好**：不影响现有功能
- **性能优秀**：使用索引，查询效率高

#### ❌ 缺点
- **需要改造代码**：所有API都需要添加 company_id 过滤
- **人工维护成本**：新增表/API需要记得添加过滤

#### 💰 成本评估
- **开发时间**: 3-5天
- **测试时间**: 2-3天
- **总工时**: 约40-60小时

---

### 方案二：**物理数据库隔离**

**核心思路**：每个租户使用独立的数据库实例

#### ✅ 优点
- **数据绝对隔离**：每个租户完全独立
- **定制化灵活**：可为特定租户定制表结构
- **性能独立**：租户间不互相影响

#### ❌ 缺点
- **成本极高**：需要多个数据库实例
- **运维复杂**：备份、升级、监控成本倍增
- **代码复杂**：需要动态切换数据库连接
- **难以迁移**：现有数据需要拆分到多个数据库

#### 💰 成本评估
- **开发时间**: 10-15天
- **测试时间**: 5-7天
- **总工时**: 约120-180小时
- **基础设施成本**: 每增加1个租户，成本增加50%-100%

---

### 方案三：**混合隔离方案**

**核心思路**：大租户独立数据库，小租户共享数据库（按 company_id 隔离）

#### ✅ 优点
- **灵活性高**：兼顾成本和隔离需求
- **可扩展性好**：大客户可随时升级为独立数据库

#### ❌ 缺点
- **架构最复杂**：需要同时维护两套逻辑
- **测试成本高**：需要测试两种模式
- **决策成本**：需要定义"大租户"标准

#### 💰 成本评估
- **开发时间**: 8-12天
- **测试时间**: 4-6天
- **总工时**: 约100-150小时

---

### 方案四：**行级安全策略（RLS）**

**核心思路**：使用数据库内置的行级安全（Row-Level Security）功能自动过滤数据

#### ✅ 优点
- **数据库层强制执行**：无法绕过，安全性极高
- **代码零改造**：应用层代码无需修改
- **透明隔离**：开发人员无感知，自动生效
- **性能优秀**：数据库内核级优化

#### ❌ 缺点
- **数据库限制**：仅PostgreSQL 9.5+、Oracle 12c+支持，**MySQL不支持**
- **调试困难**：策略在数据库层，应用层难以追踪
- **迁移代价高**：需要从MySQL迁移到PostgreSQL
- **复杂场景难处理**：多表JOIN时策略复杂

#### 💰 成本评估
- **数据库迁移**: 10-15天（MySQL → PostgreSQL）
- **策略配置**: 2-3天
- **测试时间**: 5-7天
- **总工时**: 约140-200小时
- **基础设施成本**: 数据库迁移风险高

#### 🔧 技术示例（PostgreSQL）
```sql
-- 启用RLS
ALTER TABLE orders ENABLE ROW LEVEL SECURITY;

-- 创建策略：用户只能看到自己公司的数据
CREATE POLICY tenant_isolation_policy ON orders
  USING (company_id = current_setting('app.current_tenant_id')::int);

-- 应用层设置租户上下文
SET app.current_tenant_id = 123;

-- 查询自动过滤（无需修改SQL）
SELECT * FROM orders;  -- 自动只返回 company_id=123 的数据
```

### 方案五：**Schema隔离**

**核心思路**：同一个数据库实例，每个租户使用独立的Schema（命名空间）

#### ✅ 优点
- **逻辑隔离清晰**：每个租户独立Schema，互不干扰
- **权限管理简单**：通过Schema权限控制访问
- **备份恢复灵活**：可单独备份某个租户Schema
- **成本适中**：共享数据库实例，节省资源

#### ❌ 缺点
- **MySQL支持有限**：MySQL的Schema就是Database，不如PostgreSQL灵活
- **连接池复杂**：需要动态切换Schema
- **跨租户查询困难**：超管查看全部数据需要UNION ALL
- **迁移数据复杂**：需要为每个租户创建Schema并迁移数据

#### 💰 成本评估
- **开发时间**: 6-8天
- **数据迁移**: 3-5天
- **测试时间**: 3-4天
- **总工时**: 约100-140小时

#### 🔧 技术示例（PostgreSQL）
```sql
-- 为租户创建Schema
CREATE SCHEMA tenant_company_1;
CREATE SCHEMA tenant_company_2;

-- 在各Schema中创建表
CREATE TABLE tenant_company_1.orders (...);
CREATE TABLE tenant_company_2.orders (...);

-- 应用层动态切换Schema
SET search_path TO tenant_company_1;
SELECT * FROM orders;  -- 访问 tenant_company_1.orders
```

```javascript
// Node.js代码示例
router.get('/orders', async (req, res) => {
  const tenantSchema = `tenant_company_${req.user.company_id}`;
  await pool.query(`SET search_path TO ${tenantSchema}`);
  const [rows] = await pool.query('SELECT * FROM orders');
  res.json({ ok: true, data: rows });
});
```

### 方案六：**表前缀隔离**

**核心思路**：所有表添加租户前缀，每个租户一组独立表（如 `company_1_orders`）

#### ✅ 优点
- **物理隔离**：每个租户完全独立的表
- **MySQL原生支持**：无需特殊数据库功能
- **定制化强**：可为特定租户定制表结构
- **备份灵活**：可单独导出某租户的表

#### ❌ 缺点
- **表数量爆炸**：100个租户 × 78个表 = 7800个表
- **维护噩梦**：表结构升级需要修改数千张表
- **连接池问题**：需要动态SQL拼接表名
- **性能风险**：MySQL对大量表支持有限（建议<10000张表）

#### 💰 成本评估
- **开发时间**: 8-10天
- **数据迁移**: 5-7天
- **测试时间**: 4-5天
- **总工时**: 约140-180小时
- **不推荐**: 仅适用于租户数极少（<10个）的场景

#### 🔧 技术示例
```javascript
// 动态表名查询
router.get('/orders', async (req, res) => {
  const tableName = `company_${req.user.company_id}_orders`;
  const sql = `SELECT * FROM ?? ORDER BY created_at DESC`;
  const [rows] = await pool.query(sql, [tableName]);
  res.json({ ok: true, data: rows });
});

// 初始化新租户
async function initTenant(companyId) {
  const tables = ['orders', 'equipments', 'customers', ...];
  for (const table of tables) {
    await pool.query(`
      CREATE TABLE company_${companyId}_${table} 
      LIKE ${table}_template
    `);
  }
}
```

### 方案七：**微服务多租户**

**核心思路**：每个租户部署独立的应用实例+数据库实例

#### ✅ 优点
- **绝对隔离**：应用+数据库完全独立
- **性能独立**：租户间零影响
- **安全性最高**：物理隔离，无法跨租户访问
- **可定制性极强**：每个租户可运行不同版本

#### ❌ 缺点
- **成本极高**：每租户需要独立服务器
- **运维复杂度指数级增长**：100个租户 = 100套环境
- **代码升级困难**：需要逐个升级所有租户实例
- **监控复杂**：需要监控数百个服务实例

#### 💰 成本评估
- **开发时间**: 15-20天（自动化部署脚本）
- **测试时间**: 7-10天
- **总工时**: 约180-240小时
- **基础设施成本**: 每租户约 ¥500-2000/月
- **仅适用于**: SaaS企业级客户（每客户年费>10万）

#### 🔧 架构示例
```
租户A: https://company-a.yourdomain.com → 独立应用实例 + 独立数据库
租户B: https://company-b.yourdomain.com → 独立应用实例 + 独立数据库

自动化部署:
- Kubernetes: 每租户独立Namespace + Deployment
```

### 3. 后端代码改造

#### 3.1 多租户中间件
```javascript
// server/middleware/tenantMiddleware.js
export function tenantMiddleware(req, res, next) {
  const user = req.user;
  
  if (!user) {
    return res.status(401).json({ ok: false, error: '未认证' });
  }
  
  // 超级管理员：不受限制
  if (user.role === 'super_admin') {
    req.tenantFilter = { where: '1=1', params: [] };
    req.tenantId = null;
    return next();
  }
  
  // 公司级用户：只能访问本公司数据
  if (!user.company_id) {
    return res.status(403).json({ 
      ok: false, 
      error: '用户未分配公司，请联系管理员' 
    });
  }
  
  req.tenantFilter = {
    where: 'company_id = ?',
    params: [user.company_id]
  };
  req.tenantId = user.company_id;
  
  next();
}

// 可选：允许访问共享数据（如系统级配置）
export function sharedResourceMiddleware(req, res, next) {
  const user = req.user;
  
  if (user.role === 'super_admin') {
    req.tenantFilter = { where: '1=1', params: [] };
  } else {
    req.tenantFilter = {
      where: '(company_id = ? OR company_id IS NULL)',
      params: [user.company_id]
    };
  }
  
  next();
}
```

#### 3.2 使用示例
```javascript
// server/routes/orders.mysql.js
import { tenantMiddleware } from '../middleware/tenantMiddleware.js';

router.get('/', tenantMiddleware, async (req, res) => {
  try {
    const { where, params } = req.tenantFilter;
    
    const sql = `
      SELECT o.*, c.name AS customer_name
      FROM orders o
      LEFT JOIN customers c ON c.id = o.customer_id
      WHERE ${where}  -- 自动注入租户过滤条件
        AND o.is_deleted = 0
      ORDER BY o.created_at DESC
    `;
    
    const [rows] = await pool.query(sql, params);
    res.json({ ok: true, data: rows });
  } catch (err) {
    res.status(500).json({ ok: false, error: err.message });
  }
});

router.post('/', tenantMiddleware, async (req, res) => {
  try {
    const data = {
      ...req.body,
      company_id: req.tenantId  // 自动设置company_id
    };
    
    const [result] = await pool.query('INSERT INTO orders SET ?', data);
    res.json({ ok: true, id: result.insertId });
  } catch (err) {
    res.status(500).json({ ok: false, error: err.message });
  }
});
```
