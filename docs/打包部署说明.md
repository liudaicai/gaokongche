# 高空车租赁管理系统 - 打包部署说明

## 📦 打包方式

### 方式一：使用 npm 命令（推荐）

#### Linux/Mac 系统
```bash
npm run package
```

#### Windows 系统
```bash
npm run package:win
```

### 方式二：直接运行脚本

#### Linux/Mac 系统
```bash
chmod +x scripts/package-for-deployment.sh
./scripts/package-for-deployment.sh
```

#### Windows 系统
```powershell
powershell -ExecutionPolicy Bypass -File scripts/package-for-deployment.ps1
```

---

## 🎯 打包流程

打包脚本会自动执行以下步骤：

1. ✅ **检查构建环境**
   - 验证 Node.js 和 npm 版本
   - 确保环境满足要求

2. ✅ **清理旧文件**
   - 删除旧的 `dist` 目录
   - 删除旧的打包目录

3. ✅ **安装依赖**
   - 如果 `node_modules` 不存在，自动安装生产依赖

4. ✅ **构建前端**
   - 执行 `npm run build`
   - 生成前端静态文件到 `dist` 目录

5. ✅ **创建打包目录**
   - 复制前端构建文件（`dist/`）
   - 复制后端代码（`server/`）
   - 复制配置文件（`package.json`, `.env.example`）
   - 复制数据库迁移脚本（`sql/mysql/`）
   - 复制部署文档（`docs/`）
   - 复制部署脚本（`scripts/`）
   - 创建 PM2 配置文件（`ecosystem.config.js`）
   - 创建部署说明文件（`README-DEPLOY.md`）

6. ✅ **清理不必要文件**
   - 删除测试文件（`.test.js`, `.spec.js`）
   - 删除 TypeScript 源文件（`.ts`, `.tsx`）
   - 删除开发配置文件（`tsconfig.json`, `vite.config.ts`）

7. ✅ **创建压缩包**
   - 创建 `tar.gz` 压缩包（Linux/Mac）
   - 创建 `zip` 压缩包（Windows）
   - 生成文件清单

## 🚀 使用打包文件部署

### 1. 上传到服务器

```bash
# 使用 SCP 上传（Linux/Mac）
scp gaokongche-deploy-*.tar.gz root@your_server_ip:/www/wwwroot/

# 使用 FTP 或宝塔文件管理器上传
```

### 2. 解压文件

```bash
# SSH 连接到服务器
ssh root@your_server_ip

# 进入目标目录
cd /www/wwwroot

# 解压文件
tar -xzf gaokongche-deploy-*.tar.gz

# 重命名目录（可选）
mv gaokongche-deploy-* gaokongche
cd gaokongche
```

### 3. 配置环境变量

```bash
# 复制环境变量示例
cp .env.example .env

# 编辑环境变量
nano .env
```

**必须修改的配置：**
- `DB_USER` - 数据库用户名
- `DB_PASSWORD` - 数据库密码
- `DB_NAME` - 数据库名称
- `JWT_SECRET` - JWT 密钥（至少32位随机字符串）

### 4. 安装依赖

```bash
npm install --production
```

### 5. 初始化数据库

```bash
# 执行数据库迁移脚本
mysql -u your_user -p your_database < sql/mysql/000_init_database_baota.sql
mysql -u your_user -p your_database < sql/mysql/200_add_multi_tenant_support_safe.sql
mysql -u your_user -p your_database < sql/mysql/215_create_blacklist_table.sql
mysql -u your_user -p your_database < sql/mysql/217_merge_finance_SUCCESS.sql
mysql -u your_user -p your_database < sql/mysql/221_add_finance_records_fields.sql
```

### 6. 启动服务

```bash
# 使用 PM2 启动
pm2 start ecosystem.config.js
pm2 save
pm2 startup
```

### 7. 配置 Nginx

参考 `docs/宝塔部署指南.md` 中的 Nginx 配置部分。

### 8. 验证部署

```bash
# 运行部署检查脚本
chmod +x scripts/check-deployment.sh
./scripts/check-deployment.sh
```

# 复制额外文件
cp your_file.txt "$PACKAGE_DIR/"

```bash
# 删除特定文件
find "$PACKAGE_DIR" -name "your_pattern" -delete
```

## ⚠️ 注意事项

1. **环境变量安全**
   - 打包时不会包含 `.env` 文件
   - 部署时务必创建并配置 `.env` 文件
   - 不要将 `.env` 文件提交到版本控制

2. **依赖安装**
   - 打包时不包含 `node_modules`
   - 部署时需要在服务器上运行 `npm install --production`

3. **数据库迁移**
   - 确保按顺序执行数据库迁移脚本
   - 生产环境部署前建议先备份数据库

4. **文件权限**
   - 解压后检查文件权限
   - `uploads/` 和 `logs/` 目录需要可写权限

5. **版本控制**
   - 打包文件不包含 `.git` 目录
   - 如需版本控制，请使用 Git 克隆方式部署

## 🐛 常见问题

### 问题 1: 打包脚本执行失败

**原因**: 可能是权限问题或脚本格式问题

**解决**:
```bash
# Linux/Mac: 添加执行权限
chmod +x scripts/package-for-deployment.sh

# Windows: 检查 PowerShell 执行策略
Get-ExecutionPolicy
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

### 问题 2: 前端构建失败

**原因**: 可能是依赖未安装或构建配置问题

**解决**:
```bash
# 清理并重新安装依赖
rm -rf node_modules package-lock.json
npm install
npm run build
```

### 问题 3: 压缩包过大

**原因**: 可能包含了不必要的文件

**解决**:
- 检查打包目录内容
- 确认已排除 `node_modules`、`.git` 等目录
- 查看文件清单确认

### 问题 4: Windows 打包失败

**原因**: PowerShell 执行策略限制

**解决**:
```powershell
# 临时允许脚本执行
Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process

# 或使用 npm 命令
npm run package:win
```
