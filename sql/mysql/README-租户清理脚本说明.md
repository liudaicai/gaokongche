# 租户数据清理脚本使用说明

## 📁 脚本文件

### 1. `清空所有租户数据.sql`
**用途**: 直接删除所有租户及其用户数据  
**特点**: 
- ⚠️ **不可恢复**
- 删除前显示详细信息
- 5秒等待时间用于确认
- 保留系统管理员账号

**适用场景**:
- 测试环境清理
- 重新开始租户配置
- 确定不需要保留数据

---

### 2. `安全清空租户-带备份.sql` ⭐ 推荐
**用途**: 删除所有租户，但先备份数据  
**特点**: 
- ✅ **可恢复**
- 自动创建备份表
- 备份表永久保留
- 可随时恢复数据

**适用场景**:
- 不确定是否需要恢复
- 生产环境清理（谨慎）
- 需要保留历史记录

---

### 3. `恢复租户数据-从备份.sql`
**用途**: 从备份表恢复租户数据  
**前提**: 已执行过"安全清空租户-带备份.sql"  
**特点**: 
- 一键恢复所有数据
- 自动验证备份表
- 恢复后可选清理备份表

---

## 🚀 使用方法

### 方案A：直接删除（不可恢复）⚠️

```bash
# 执行清空脚本
mysql -u root -p gaokongche < "d:\kaifa\4\sql\mysql\清空所有租户数据.sql"
```

**结果**:
- ✅ 所有租户已删除
- ✅ 所有租户用户已删除
- ✅ 系统管理员保留
- ❌ 无法恢复

---

### 方案B：安全删除（可恢复）✅ 推荐

#### 步骤1：删除并备份
```bash
mysql -u root -p gaokongche < "d:\kaifa\4\sql\mysql\安全清空租户-带备份.sql"
```

**结果**:
- ✅ 所有租户已删除
- ✅ 数据已备份到 `company_verifications_backup` 和 `users_backup` 表
- ✅ 可随时恢复

#### 步骤2：（可选）恢复数据
```bash
mysql -u root -p gaokongche < "d:\kaifa\4\sql\mysql\恢复租户数据-从备份.sql"
```

**结果**:
- ✅ 所有租户已恢复
- ✅ 所有用户已恢复
- ✅ 数据完整无损

## 📊 删除内容

### 会被删除的数据
- ✅ `company_verifications` 表的所有记录（租户信息）
- ✅ `users` 表中 `company_id IS NOT NULL` 的记录（租户用户）

### 会保留的数据
- ✅ `users` 表中 `company_id IS NULL` 的记录（超级管理员）
- ✅ 系统配置数据
- ✅ 其他业务数据

## ⚠️ 注意事项

### 1. 订单检查
如果存在关联订单（`orders.lessor_company_id` 指向租户），脚本会提示：
```
⚠️ 存在关联订单，建议检查后再删除
```

**建议**：先清理或备份订单数据

### 2. 外键约束
如果数据库设置了外键约束，删除可能失败。解决方案：
```sql
-- 临时禁用外键检查
SET FOREIGN_KEY_CHECKS = 0;
-- 执行删除
-- ...
-- 重新启用外键检查
SET FOREIGN_KEY_CHECKS = 1;
```

### 3. 备份建议
即使使用"安全清空"脚本，也建议先导出整个数据库：
```bash
mysqldump -u root -p gaokongche > backup_before_clean.sql
```

## 📞 问题排查

### 问题1：脚本执行失败
**原因**: 可能是权限不足或语法错误  
**解决**: 使用 root 用户执行，检查MySQL版本兼容性

### 问题2：删除后仍有数据
**原因**: 可能有外键约束或触发器  
**解决**: 检查数据库约束，手动删除残留数据

### 问题3：恢复失败
**原因**: 备份表不存在或数据冲突  
**解决**: 检查备份表是否存在，清空目标表后再恢复
